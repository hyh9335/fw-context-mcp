## How G11 (FreeRTOS) and G12 (Mbed TLS) were produced

Both M6.5 real-project corpus tests used the SAME approach:

1. **Direct libclang parsing** via the Python `clang.cindex` binding — NOT CMake, NOT compile_commands.json, NOT a real compiler build.
2. The `extract_build_facts()` function in `full_build_gt.py` calls `parse_tu()` which calls `clang.cindex.Index.create().parse()`.
3. The compiler target was `--target=x86_64-pc-windows-msvc` with NO stdlib include paths.
4. Build configurations were created by varying `-D` defines and include directories.
5. GT was generated by merging per-source `BuildFacts` objects.
6. Shadow differential ran the M6 `BuildSetStore` against the GT canon set.

### Critical finding

The M6.5 real-project corpora did NOT produce `compile_commands.json`. The §10 requirement for compile_commands.json is a NEW requirement that M6.5 did not satisfy. M7.0A must create proper compile_commands.json for fw-context to consume.

## Reproducibility Assessment

### What can be reproduced exactly
- Source checkout (pinned commits present and clean)
- Build configurations (defined in `test_freertos.py` and `test_mbedtls.py`)
- GT generation (`extract_build_facts()` is deterministic for a given libclang version)
- M6 shadow differential (in-memory SQLite, deterministic)

### What CANNOT be reproduced from M6.5 evidence
- **compile_commands.json** — M6.5 never created one. M7.0A §10 requires this.
- **Real compilation** — M6.5 never compiled the sources with a real compiler. M7.0A §10 requires "compile succeeds."
- **fw-context index consumption** — M6.5 never ran `fw-context index` on these corpora. M7.0A §10 requires "fw-context can consume those compile commands."

### Toolchain note
M6.5 used the Python `clang.cindex` binding with target `--target=x86_64-pc-windows-msvc`. The system has LLVM 22.1.8 installed at `C:\Program Files\LLVM\bin\` with `clang.exe` and `clang++.exe` available. CMake is NOT installed. The M7.0A baseline will generate compile_commands.json manually (like the M6.5 synthetic corpora do) rather than requiring CMake.

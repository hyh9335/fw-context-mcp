## FACTS

- A2-F1 FACT — The goal's artifact chain is explicit: inspect source → discover fault mechanisms/failure modes → reconstruct causal mechanism + execution/configuration conditions → derive detection/diagnosis rules → attach evidence + confidence for human audit (inputs/GOAL_CONTRACT.md L3–11). "From source code" is central; logs/traces may validate/enrich but must not redefine the goal into log mining.
- A2-F2 FACT — Substrate defect ledger with direct fault-reasoning impact (outputs/FACT_LEDGER.json F-R0-04..F-R0-09, F-R0-16, F-R0-17):
  - F-V1-001: per-context macro values ARE stored in the DB but no supported consumer surface (lookup/search/explain/export) exposes them; one context's expanded_value is self-inconsistent.
  - F-V1-007 (amends F-V1-002; C-02 RESOLVED_BY_AMENDMENT): ANY single-line definition stores symbols.source='' and is invisible to search_bodies; confirmed on G13 which has no conditionals at all; one-line accessors are a very common C style. get_source masks it via disk fallback (source_origin='disk').
  - F-V1-003: bare generator writes one shared compile_commands.json so the last variant's defines win; group_equivalent_variants reports transport_send "equivalent" across variants A/B/C although B compiles a different branch; get_source(variant='B') served the INACTIVE uart-branch body as live with no stale warning (F-R0-06). The defect is invisible to the product's own consistency checks.
  - F-V1-004: transitive callback registration (may-target through a registration-API call argument, register_cb(plus1)) does not resolve; direct flows do. Reachable callback set silently under-reported.
  - F-V1-005: on compile_commands-only projects find_dead_code misreports the plainly live chain main→live_root→live_leaf as graph_unreachable because the root set requires a build-attested linker script and no config key declares one; correctly classifies a dead SCC and KEEP-protection on the linker-script oracle.
  - F-V2-001: get_vector_table returns a false "No vector table" for the standard CMSIS6 C-template form (typedef'd function-pointer array, cast first element) while the assembly form IS recognized; no oracle defect found (C-03: an empty vector result can be contracted-honest OR a false absence).
  - F-V2-002: lookup_symbol exact=True silently relaxes to an unrelated-symbol fallback when the name is absent (marked _fallback) — automated existence checks get false positives.
  - F-V1-008: all query surfaces cap at limit≤100 with no pagination; >100 same-name rows cannot be enumerated.
- A2-F3 FACT — ifdef-filtered content is the substrate's default truth channel; a file changed after indexing is served from DISK with source_origin='disk' + stale_warning; an all-blank file is marked all_lines_inactive, not empty; llm_analysis is model-written and must never be quoted as fact (fw-context tool contracts; AGENTS.md fw-context section).
- A2-F4 FACT — Closest published pattern is neuro-symbolic: [IRIS](https://arxiv.org/html/2405.17238v3) — an LLM infers taint specifications (sources/sinks), a static engine (CodeQL) extracts whole-repository vulnerable paths, and an LLM does contextual triage of each reported path with JSON verdict + explanation. Results: CodeQL 27/120 vs IRIS+GPT-4 55/120; best published AvgFDR 84.8%, refined to ~46% on a 50-alarm manual sample. Detecting vulnerabilities requires whole-project reasoning LLMs cannot do alone.
- A2-F5 FACT — IRIS itself documents limits: some fault classes (CWE-78 gadget chains, external side effects such as file writes) exceed static reach and are deferred to dynamic analysis (same source).
- A2-F6 FACT — FMEA is the established failure-mode artifact with an explicit cause→mode→effect→detection structure ([ASQ](https://asq.org/quality-resources/fmea), [Wikipedia](https://en.wikipedia.org/wiki/Failure_mode_and_effects_analysis)).
- A2-F7 FACT — Source-only decidable rules are an established category: MISRA C:2012 Rule 2.1 (unreachable code) and the unused-code rule set are checkable statically with a documented rationale ([MathWorks MISRA 2.1](https://www.mathworks.com/help/bugfinder/ref/misrac2012rule2.1.html), [AdaCore](https://learn.adacore.com/courses/SPARK_for_the_MISRA_C_Developer/chapters/08_unreachable_and_dead_code.html)).
- A2-F8 FACT — Passing surfaces established at HEAD d8f08a4 (F-R0-13): call graph, indirect call sites, dead-code L1/L2 with SCC detection, vector tables (assembly form), variant indexing, semantic search, honest empty results on unsupported-arch queries, large public-project indexing (Zephyr/NuttX/RIOT/FreeRTOS/CMSIS).
- A2-F9 FACT — No fault-discovery/rule-generation pipeline code exists in the repo (F-R0-18); the Agent is greenfield on this substrate with a known defect ledger.
- A2-F10 FACT — This repo's Windows environment lacks clang/cmake/ninja/make/MSVC (F-R0-14), so a clang co-oracle is not deployable in every environment the evidence was gathered in (WSL has it).

## INFERENCES

- A2-I1 INFERENCE (answers OQ1+2; from A2-F1, F4, F6) — Operational definition: "discover a fault from source code" = emit a **FaultMechanismRecord**: {fault class; hypothesis statement; causal chain of source-anchored hops, each hop a named relation (direct call / callback / condition / data flow) with a certainty value; trigger conditions (build / variant / runtime); effect and observable; detection-rule candidate; diagnosis-rule candidate; evidence list (file:line + tool + query); confidence; falsification test}. A bare bug-pattern label is NOT discovery — the IRIS alert (whole-repo path + explanation) is the precedent (A2-F4). The target artifact is the SEQUENCE pattern → mechanism → rules (OQ2), not any single item.
- A2-I2 INFERENCE (answers OQ6) — MVP-critical relations, ranked by how many fault classes break without them, with required certainty: (1) direct call — exact; supported. (2) callback registration including transitive registration-API flows — exact; BROKEN (F-V1-004). (3) compile conditions per analyzed build — exact; explain_condition context resolution is nondeterministic across runs (F-R0-15) and needs a re-run verification protocol. (4) variant identity — exact; BROKEN and self-masking (F-V1-003). (5) reachability — root-set-attested or UNKNOWN; never "unreachable" without root attestation (F-V1-005). (6) vector/handler binding — two-form cross-checked; C-form false absence (F-V2-001, C-03). (7) cross-function data flow — "may", synchronous only (trace_data_flow contract; queue semantics out of scope). (8) async/dispatch — "may", bridge-listed RTOS only (mbed-os/Zephyr/FreeRTOS built-ins).
- A2-I3 INFERENCE — Architecture pattern: **catalog proposes, substrate disposes**. The ten fault classes in the role brief become human-reviewed hypothesis templates; each template demands a fixed query bundle against the substrate; the LLM assembles evidence and triages — it never free-form scans the repo. This is IRIS's structure transplanted from security taint to failure modes (A2-F4 + A2-F6), and it is the primary false-positive control: an ungrounded hypothesis cannot pass the evidence gate.
- A2-I4 INFERENCE (answers OQ3+4) — Rule taxonomy: **R-S** static code rule (source-anchored pattern/property; source-only GT decidable — MISRA 2.1 precedent, A2-F7); **R-I** invariant (state property; source-only GT when all writes are enumerable via find_variables); **R-B** build/config rule (needs build DB — currently defective, F-V1-001/F-V1-003); **R-O** runtime observable rule (log/counter/watchdog signature; GT requires traces — validation only per GOAL_CONTRACT L11); **R-C** causal diagnosis rule (symptom → ranked hypotheses; GT needs a paired symptom/cause corpus). Source-only GT: R-S yes; R-I partially; R-B conditional; R-O no; R-C no.
- A2-I5 INFERENCE (answers OQ5) — Hallucination control = evidence gates enforced in the record schema, not in the prompt: **E1** every causal-chain hop is a proven edge (certainty=exact) or labeled possible with a candidate list; **E2** condition/variant claims are evaluated for the analyzed build (check source_origin/stale_warning, A2-F3); **E3** absence claims ("no handler / no check / no sanitizer") require: recorded query surface + enumeration bound (F-V1-008) + a silence-risk annotation (F-V1-007: source='' is not proof of no logic) — absence is the highest-risk claim class because FOUR independent substrate mechanisms fabricate existence/absence (F-V1-007, F-V1-008, F-V2-001, F-V2-002); **E4** reachability claims name the root set used (F-V1-005); **E5** vector claims cross-check both table forms (C-03); **E6** provenance = file:line from match_lines/end_line only, never llm_analysis (A2-F3); **E7** cross-variant equivalence claims are banned from current surfaces (F-V1-003 asserts the opposite of truth).
- A2-I6 INFERENCE — Failure direction matters for risk: F-V1-003 is the only ledger defect that ASSERTS a false positive fact (equivalence where divergence exists); every other defect fails toward silence (missing evidence), which the E-gates can catch. Therefore variant-misconfig conclusions must be structurally excluded at MVP, not merely downgraded in confidence.
- A2-I7 INFERENCE — Source-only honest limits, declared per record: timing/races, hardware/DMA interactions, queue-ordering semantics, value-dependent behavior beyond compile-time constants (A2-F5), and "intent" — with no spec, intended behavior must be derived as code-internal consistency properties (paired-call conventions, symmetric error handling) and labeled derived-intent, never quoted as a specification.
- A2-I8 INFERENCE (answers OQ8; role: fw-context is not the only acquisition mechanism) — Division of labor: the build system owns defines/compile DB/linker scripts (the true source of the dead-code root set, F-V1-005); clang -dM/-E per TU owns macro-value ground truth where clang exists (bypasses F-V1-001's missing consumer; unavailable on Windows here, A2-F10 → macro-dependent claims marked UNCERTAIN); tree-sitter/grep own token-level patterns; fw-context owns indexed semantic relations + ifdef-filtered truth + cross-TU graphs; logs/traces validate only (GOAL_CONTRACT L11).
- A2-I9 INFERENCE (answers OQ9) — First public end-to-end case candidate: "unhandled external interrupt → Default_Handler stop" on an assembly-form CMSIS fixture. Oracle is source-decidable (the slot is aliased to Default_Handler or not); mechanically supported today (get_vector_table unhandled_only, A2-F8); exercises vector binding, reachability, and the full record schema. The C-form variant is deferred until C-03 is resolved.
- A2-I10 INFERENCE (answers OQ7) — Uncertainty budget: existence claims (handler/config present?) = zero tolerance (bypass lookup fallback, F-V2-002); relation claims = mandatory certainty field; possible edges never enter a final causal chain without corroboration; condition claims = exact per analyzed build or UNCERTAIN; quantitative dead/live claims = only with root attestation; absence claims = always annotated. The Agent may absorb uncertainty in RANKING (which hypotheses to explore) but not in ASSERTION (what a record states).
- A2-I11 INFERENCE — Fault-class → substrate-status map (classes from role brief; status from ledger facts):

| Fault class | Required source facts | Rule types | Substrate status today |
|---|---|---|---|
| Init/config/order | call path, ordering, conditions, macro values | R-S,R-B,R-C | call graph OK; macro values stored but unexposed (F-V1-001); condition nondeterminism (F-R0-15) |

| Concurrency/ownership | shared globals, ISR-context membership | R-I,R-C | global refs OK (find_variables); ISR context only via vector+bridges |
| Variant misconfig | per-variant bodies + defines | R-B | broken (F-V1-003; inactive body served as live, F-R0-06) |
| Error/retry/fallback | control flow, handler existence, dead paths | R-S,R-C,R-O | existence false-positives (F-V2-002); root-set breakage on compile_commands-only projects (F-V1-005) |

## ASSUMPTIONS

- A2-A1 ASSUMPTION — MVP targets C/C++ projects with compile_commands.json (the substrate's own precondition), with single-variant analysis as the default.
- A2-A2 ASSUMPTION — ~10–20 human-reviewed hypothesis templates cover the MVP fault space; open-ended discovery is out of MVP scope.
- A2-A3 ASSUMPTION — A human-audit workflow will consume FaultMechanismRecords; downstream automated consumers are not MVP.
- A2-A4 ASSUMPTION — The C-01 verdict collision (READY vs NOT_READY) changes only the trust level of surfaces, not which surfaces exist; the E-gate design holds under either adjudication.

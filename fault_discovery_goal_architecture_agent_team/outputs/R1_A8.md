# R1 — A8 Alternative Architect

Evaluation basis: R0 freeze (FACT_LEDGER.json, CONTRADICTIONS.json), GOAL_CONTRACT.md, ANTI_ANCHOR.md, product docs (docs/tools.md, KNOWN_LIMITATIONS.md). Default decomposition under challenge: fw-context as evidence substrate + new Agent layer on top. Alternatives evaluated: Alt-1 LLM-first (reasoning model + grep/clang CLI, fw-context dropped), Alt-2 static-analysis-first (CodeQL/Clang-analyzer/custom AST passes as rule engine, LLM triage only), Alt-3 build-graph-first (per-variant compile DBs / Kconfig primary, semantics secondary), Alt-4 minimal-CLI (thin script bundle, no index, rebuilt per query).

## FACTS

- F8-01 (FACT; F-R0-18): No Fault-Discovery-Agent code exists anywhere in the repo — only the fw-context substrate, validation harnesses, and this review pack. Every candidate decomposition therefore pays identical agent-layer build cost; substrate choice does not gate time-to-first-rule.
- F8-02 (FACT; F-R0-13): Frozen substrate strengths: real stdio MCP (cold 453–781 ms, warm ~15 ms, recommended 5000 ms timeout, win→win / wsl→wsl / win-launcher→wsl); fanout 1→250 linear (13.2 s @ 250 TUs / 2250 symbols); A1–A8 adversarial mutation classes + repeated-mutation index integrity; large public-project indexing (Zephyr/NuttX/RIOT/FreeRTOS/CMSIS).
- F8-03 (FACT; F-V1-003): The only CRITICAL defect sits in the build/variant dimension: a bare generator writes one shared compile_commands.json so the last variant's defines win; compare_variants and group_equivalent_variants then validate the collapsed data (self-masking); get_source(variant='B') served the INACTIVE uart-branch body from disk as if live, with no stale warning.
- F8-04 (FACT; F-V1-007): Any single-line definition stores symbols.source='' and is invisible to search_bodies; one-line accessors are a very common C style (G01/G03/G12/G13 cross-confirmed).
- F8-05 (FACT; F-V1-001): Per-context macro values ARE stored (macros table, def_source=command_line) but no supported consumer surface exposes them; one context shows value/expanded_value self-inconsistency ('1' vs '2').
- F8-06 (FACT; F-V1-004): Direct function-pointer flows resolve; the transitive registration flow (may-target through a registration-API call argument, register_cb(plus1)) does not — the reachable callback set is silently under-reported.
- F8-07 (FACT; F-V1-005): On compile_commands-only projects, find_dead_code misreports the plainly live chain main→live_root→live_leaf as graph_unreachable, because the root set demands a build-attested linker script and no configuration key can declare one.
- F8-08 (FACT; F-V2-001, F-V2-002): get_vector_table returns false "No vector table" for the standard CMSIS6 C-form while the asm form IS recognized (WRONG_ANSWER, no oracle defect found); lookup_symbol exact=True silently relaxes to an unrelated-symbol fallback, violating the documented empty contract (false positives for automated existence checks).
- F8-09 (FACT; F-R0-14 + KNOWN_LIMITATIONS.md §3/§5): The frozen Windows host has no clang/cmake/ninja/make/MSVC. The indexer does not invoke a compiler — libclang parses compile_commands.json flags directly; the clang binary is needed only for asm preprocessing (clang -E). The substrate core therefore runs on this host; a clang-binary-based tool does not.
- F8-10 (FACT; F-R0-11, FR-R1): Per-context (rows/3) storage semantics were upheld as the intended truth model when the duplicate-USR "corruption" claim was refuted with anti-tautology verification.
- F8-11 (FACT; F-R0-20): The user designates fw-context-mcp as "a candidate evidence-acquisition / semantic-analysis substrate" whose scope is a subject of this review — not the goal itself.
- F8-12 (FACT; GOAL_CONTRACT non-goals): "perfect general-purpose static analysis", "solving all compiler/linker semantics", "making fw-context a standalone best-in-class product", "exhaustively modeling every RTOS before an MVP" are non-goals.
- F8-13 (FACT; docs/tools.md): Indexing supports per-variant scoping (--variant/--variants/--image) and per-build DB rows (fw-context db list/stats); queries accept variant/image parameters — the variant dimension is first-class schema, distinct from its broken delivery (F8-03). The substrate surface is broad: ~30 tools across search/source/call-graph/inheritance/maintenance categories (countable in the MCP tool catalog).

## INFERENCES

- I-1 (INFERENCE): The compile-DB/config-resolution problem exposed by F-V1-003 is not substrate-specific — every alternative must solve it to honor "execution/configuration conditions" (goal item 3): Alt-1 re-derives macro environments per prompt with no provenance; Alt-2 needs N per-config extraction DBs; Alt-3 makes the problem primary; Alt-4 must pick flags per TU before any AST query. The defect indicts the current generator, not the indexed approach.
- I-2 (INFERENCE): On the frozen environment, toolchain-dependent alternatives are excluded as specified: Alt-2 (CodeQL/Clang-analyzer extraction) and Alt-4-as-written (clang -ast-dump) require a clang binary the host lacks (F8-09). Only a libclang-binding indexer and Alt-1 (LLM+grep) run there today. Alt-4 could switch to a libclang binding — but per-TU result caching then reintroduces an index, minus the mutation-integrity machinery F8-02 validated.
- I-3 (INFERENCE): Alt-4's no-index position collapses under the rule-evaluation workload: any rule referencing cross-TU call structure must re-derive edges per query (O(project) each); the first caching layer is an unmanaged index. Rules are re-evaluated repeatedly (regression/CI/post-refactor, A-2), which amortizes a persistent evidence layer.
- I-4 (INFERENCE): Alt-2 is the strongest challenger on goal items 4–5 (rules ARE deterministic queries; findings carry file:line; FP control via query refinement) and is likely strictly stronger than the substrate today on callback-registration dataflow (F8-06) — may-target-through-argument is native dataflow for CodeQL-class engines (not measured here, U-3); its per-config DBs also do not inherit F-V1-003's shared-DB self-masking. But it is structurally weakest on items 2–3: rule languages find only encoded shapes, not open-ended mechanism discovery, and store no per-branch ifdef truth inside a TU.
- I-5 (INFERENCE): Alt-3 alone discovers no mechanism faults — it answers "which code is live under which config", not "what is wrong"; it is a dimension to fuse, not a standalone decomposition. Betting the goal on it means betting on the surface holding the only CRITICAL defect (F8-03) plus N-variant build cost.
- I-6 (INFERENCE): Alt-1's structural failure mode is exactly what F-V1-003's disk-fallback did once — reading an inactive branch as live with no marker — except in Alt-1 it happens on every read of every conditional file, unmarked, with no config_hash provenance. Honest credit to Alt-1/Alt-4: reading raw disk sidesteps F8-04 (single-line emptiness) and F8-05 (macro observability) entirely — the two classes where the substrate currently under-delivers; the trade is loss of per-branch filtering and provenance.
- I-7 (INFERENCE): Time-to-first-useful-rule ranking: Alt-1 hours (lowest reliability floor, no regression target); Alt-4 days (cross-TU rules stall); substrate+agent and Alt-2 weeks (agent layer missing everywhere per F8-01; Alt-2 adds extraction infra). Because no architecture has an agent today, "finish the substrate first" is implied by no schedule argument — this defuses C-04's completion-bias pull.
- I-8 (INFERENCE): clangd: per-TU exact AST + background cross-refs, but editor-LSP oriented, opaque/unqueryable index, one active config at a time, no per-variant rows, no provenance, no ISR/vector concept, and blocked on the frozen host (no clang binary, F8-09). Tree-sitter: zero build deps, fast, but no preprocessor semantics — cannot deliver per-context truth at all; at most a cheap first-pass filter. Neither is a rule-evaluation engine.
- I-9 (INFERENCE): ISR/vector-registration knowledge is a substrate feature NO alternative provides out of the box (CodeQL/clangd/tree-sitter/clang -ast-dump have no vector-table concept) — a genuine differentiator for firmware fault classes, currently degraded by F-V2-001's false absence on the CMSIS6 C-form: it must be fixed, not shipped as-is.
- I-10 (INFERENCE): The substrate defect set splits: (a) observability gaps fixable at surface level (F8-04, F8-05); (b) two wrong-answer tool contracts fixable at contract level (F8-08); (c) one design-level divergence class (F8-03); (d) root-set/graph coverage limits needing an external oracle (F8-06, F8-07). Only (c)+(d) bear on decomposition choice; (a)+(b) argue for narrower scope and stricter contracts, not replacement.

## ASSUMPTIONS

- A-1 (ASSUMPTION): Target projects resemble the validated class: exportable compile_commands.json (CMake/make/Zephyr/PlatformIO per docs/tools.md), possibly on compiler-less hosts.
- A-2 (ASSUMPTION): Rules must be re-evaluated repeatedly (regression, CI, post-refactor), not derived once — this is what justifies persistent evidence over per-query recomputation.
- A-3 (ASSUMPTION): Auditability (goal item 5) requires each rule to have a deterministic evaluation path a human can re-run without re-running the LLM.
- A-4 (ASSUMPTION): Compilation/preprocessing is an acceptable ground-truth oracle for "what compiles under which flags", tolerable as a slow path.
- A-5 (ASSUMPTION): MVP does not require multi-variant breadth; single-variant per-context truth plus direct config reading (Kconfig/prj.conf) covers goal item 3 initially.

## UNCERTAINTIES

- U-1 (UNCERTAINTY): Whether the corporate environment will ever provision clang/toolchains on primary hosts — would reopen Alt-2/Alt-4 viability (absence today is fact, F8-09; future policy is not).
- U-2 (UNCERTAINTY): C-01 adjudication (READY vs NOT_READY) is pending; it affects remediation sequencing, not the decomposition question — zero-sunk-cost reasoning excludes both verdicts.
- U-3 (UNCERTAINTY): CodeQL firmware extraction quality on custom toolchains was never measured here; the frozen set contains no external-tool evidence.
- U-4 (UNCERTAINTY): Real target scale: fanout was validated to 250 TUs only (F8-02); Alt-4 per-query cost and substrate behavior at 1000+ TUs are unmeasured.
- U-5 (UNCERTAINTY): Whether kconfiglib-class resolution can deliver per-variant effective configs without full per-variant builds — untested in this evidence set.

## TOP IMPLICATIONS & QUESTIONS

- P-1 (PROPOSAL): The substrate+agent KIND of decomposition survives; fw-context's SCOPE does not. A greenfield spec is ≈10–12 evidence primitives: per-context ifdef views; refs graph with certainty labels; macro-context query surface; ISR/vector-registration view; provenance (config_hash/source_origin) on every answer; refusal-not-warn semantics on divergent/stale views; deterministic pagination; exact-match-never-falls-back. Embeddings, llm_analysis, PageRank/hotspots, semantic search = optional recall aids, never evidence.
- P-2 (PROPOSAL): Add two layers absent from every candidate including the substrate: (a) compiler-oracle arbitration — compile/preprocess to adjudicate substrate-vs-rule disagreements (directly answers F8-07's root-set gap and F8-03's truth question, A-4); (b) rules-as-deterministic-queries — each rule stored as an executable predicate over the evidence kernel, so audit = re-run (absorbs Alt-2's strongest property without its extraction infra, A-3).
- P-3 (PROPOSAL): Defer the variant/compare/group surface out of the MVP — the only CRITICAL defect lives there (F8-03) and A-5 says the MVP needs single-variant per-context truth plus config conditions. Fix the fallback/empty contracts (F8-08) at design time; cheap when specified, expensive as retrofits.
- P-4 (PROPOSAL): Promote macro-context (F8-05) to a first-class query surface: goal item 3 is unreachable without it in every alternative (I-1).
- Q-1: Does any real target require multi-variant compare at MVP, or is single-variant per-context truth sufficient? (decides P-3 timing)
- Q-2: What oracle budget (compile time per rule evaluation) is acceptable? (decides how often P-2a arbitration runs vs staying on indexed evidence)
- Q-3: Which fault class must the first rule pack cover? If callback/ISR-registration chains dominate, borrow Alt-2-class dataflow for that slice (F8-06 gap) rather than extending substrate heuristics.

## ZERO-SUNK-COST ANSWER (mandatory, explicit)

If this project started today with zero sunk cost, we would NOT choose fw-context-mcp as currently scoped: a broad ~30-tool general code-intelligence product (F8-13) with embeddings, LLM analysis, PageRank/hotspots, and a variant-compare surface is over-scoped for this goal and carries the observability defect tail (F8-04, F8-05), two wrong-answer contracts (F8-08), and the only CRITICAL defect (F8-03).

We WOULD still choose the same KIND of decomposition — a persistent, per-context evidence kernel beneath a reasoning agent — for four evidence-grounded reasons, none of which is sunk cost: (1) the rule-evaluation workload amortizes an index; no-index designs either pay O(project) per cross-TU query or grow an unmanaged cache (I-3); (2) per-context truth requires managed flag/config resolution that every alternative must re-solve, with provenance the alternatives lack (I-1, I-6); (3) the frozen environment runs a libclang-binding substrate but not compiler-based extraction, excluding Alt-2 and Alt-4-as-specified on this host class (F8-09); (4) auditability (goal item 5) demands deterministic re-evaluation and provenance that LLM-first structurally cannot provide (I-6), while pure rule-engine discovery cannot generate novel mechanisms (I-4).

What changes concretely: (i) scope the substrate down to the P-1 evidence-kernel primitive set, with refusal-not-warn and exact-no-fallback contracts fixed at design time; (ii) add compiler-oracle arbitration as a first-class layer — the substrate becomes fast-path evidence, the compiler is the arbiter (P-2a); (iii) express rules as deterministic queries evaluated over the kernel, absorbing Alt-2's auditability without its extraction cost (P-2b); (iv) defer the variant/compare/group surface out of the MVP and re-earn it against a real multi-variant project (P-3); (v) keep all LLM reasoning in the agent layer, never inside the substrate (llm_analysis is already contract-barred from evidence). fw-context-mcp's zero-sunk-cost role: a candidate implementation of the evidence kernel whose one inherited asset a greenfield could not cheaply replicate is the validated mutation-integrity + stdio record (F8-02); everything else it must re-earn against the kernel spec — and the variant surface it must re-earn last.

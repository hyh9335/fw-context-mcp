## INFERENCES

### I-A6-01 — Two-level evaluation, strictly separated
Level-1 = fw-context fact evaluation (exists: golden pack + independent oracles; NOT_READY at d8f08a4). Level-2 = Agent hypothesis/rule evaluation (does not exist; no fixture, no oracle, no metric definition anywhere in the repo — F-A6-08). Level-2 scores are meaningless on fixtures whose Level-1 facts are wrong: the 7 FAIL_PRODUCT surfaces (F-A6-05) must either carry substrate-caveat scoring branches or be excluded and reported separately. [INFERENCE]

### I-A6-02 — Ground truth constructible source-only, per rule type
| Rule type | Source-only GT | Form |
|---|---|---|
| Build-condition rules (active branch, affected/unaffected contexts) | FULL | per-context truth table, oracle = fixture #if structure + clang -E + compile_commands (G03/G04 pattern) |
| Callback/registration rules | PARTIAL | registration topology exact; invocation order/timing is runtime-only → GT = may-target sets + evidence_required + uncertainty markers (G06 pattern) |
| Reachability rules | PARTIAL | call-graph GT source-only; final-binary retention needs linker/ELF — a build artifact but still objective (G07 `link_command_hint`) |
| Vector/slot rules | FULL | fixture array initializer + CMSIS documented slot table (G10) |
| Resource-bound invariants | PARTIAL | bounds/producer-consumer topology exact; exhaustion condition is runtime → GT = source facts + forbidden-overclaim list |
| Enumeration/completeness rules | FULL | generator-written exact counts (G13 pattern) |
| Symbol-identity (negative) rules | FULL | binary: symbol absent → no substitution, no explanation built from a substitute |
| Mechanism-class of a fault | ONLY VIA PLANTED FAULTS | the mutation diff defines the mechanism class a priori; natural-fault mechanism classes are not source-constructible without a labeled corpus |

[INFERENCE from F-A6-01..04] This table answers OPEN_QUESTIONS item 4 (which rule types validate with source-only GT).

### I-A6-03 — Metric set with scoring procedures (maps to mandated metric list)
1. **Hypothesis precision/recall** — on planted-fault fixtures (controlled mutations of clean bases): P = correct + evidenced hypotheses / all emitted; R = faults recovered / planted. Exact GT exists by construction.
2. **Evidence correctness** — every claim must carry file:line anchors; an automatic checker verifies the anchor resolves and the anchored fixture text entails the claim. Unanchored ⇒ claim unsupported.
3. **Causal-chain correctness** — GT defines the allowed chain (e.g., registration → dispatch → handler) and forbidden edges (no invented direct CALL; G06 pattern). Score = chain matches allowed graph; any invented edge = FAIL.
4. **Rule correctness** — the emitted rule predicate is evaluated against the per-context GT truth table (G03 pattern); exact match required, partial credit predefined at authoring time.
5. **FP control** — clean (un-mutated) fixtures must yield zero definite fault claims; near-miss fixtures (linker-kept symbol reported as dead; direct-called "callback"; substitute-symbol explanation) bound discriminator specificity (G07 `forbidden_definite_dead` / G02 `forbidden` patterns generalized).
6. **Unsupported-claim rate** — any definite claim contradicted by GT or lacking anchors forces scenario FAIL (mirrors the pack verdict rule, F-A6-05).
7. **Context correctness** — per-context fact tables incl. context identity (G02/G03/G04 pattern), exact match.
8. **Reproducibility** — run the Agent twice per fixture; score verdict agreement. Because explain_condition is nondeterministic at Level 1 (F-A6-07), Level-2 stability must be measured separately and blame pinned: same-input divergence with stable Level-1 facts = Agent defect.
9. **Review burden** — median count of evidence items a human must open to confirm one emitted rule; measured on a fixed rubric. [INFERENCE]

### I-A6-04 — Holdout protocol
(a) **Synthetic layer**: extend the G13 generator pattern — a seeded mutation generator derives fault fixtures from clean golden bases; dev set seed S1 visible during Agent construction, holdout seed S2 sealed; `expected.json` written by the generator before any Agent run. (b) **Public layer**: real bug-fix commits mined from Zephyr/NuttX history at pinned parent SHAs (F-A6-10); fault = parent checkout, GT = the actual fix diff (localization + mechanism class); the diff is never shown to the Agent. (c) **Anti-tautology**: ORACLE_POLICY:12 extended — GT is never authored from any fw-context or Agent run output. (d) **Level-1 gate**: re-run the golden pack at the scored HEAD immediately before Agent scoring; fixtures on substrate-failing surfaces are scored with caveat branches or excluded, never silently counted. (e) **Sealed negative probes**: clean twins of each fault fixture run under the same protocol. [INFERENCE; PROPOSAL for the protocol]

### I-A6-05 — Verdicts on the 8 scenario files
Rubric: can the scenario become an objective MVP test using existing pack oracle patterns without inventing new GT semantics? "usable-as-is" = trivially authorable GT; "needs-oracle-extension" = existing pattern extends but new contract parts or substrate-caveat branches are required; "not-objective" = cannot be made objective source-only.

### I-A6-06 — OQ10 in measurable terms: what proves a local optimum
Define **substrate-sufficiency** S = fraction of holdout planted faults for which every fact in the GT evidence chain is retrievable via existing fw-context surfaces (audited per fault against the expected.json evidence list). Attribute every holdout miss to exactly one bucket: {substrate-fact-missing, agent-missed-despite-facts-present, protocol/GT-defect}. **Current architecture is a local optimum iff: (1) the dominant miss bucket is agent-missed-despite-facts-present, AND (2) the marginal recall gain of the two highest-value substrate fixes is < ε (pre-registered, e.g. 5 percentage points) on the holdout.** This is the objective instrument for contradiction C-04: if dev-set sufficiency S ≥ 80% already, the evidence says stop polishing the substrate and build the Agent; if the dominant bucket is substrate-fact-missing with individually cheap fixes, the architecture is NOT at a local optimum and substrate work continues with named items. [INFERENCE; PROPOSAL]

## ASSUMPTIONS

- **A-A6-01 [ASSUMPTION]** The Agent MVP can be constrained to a structured output schema (hypothesis, mechanism class, rule predicate, evidence anchors, confidence, limitations) — required for automatic scoring; if output is free text only, scoring needs human raters and metric 9 (review burden) absorbs the cost.
- **A-A6-02 [ASSUMPTION]** Fixture authoring effort (~1–2 dev-days per exact-GT fixture family reusing existing golden bases) is available in MVP scope.
- **A-A6-03 [ASSUMPTION]** The holdout can actually be sealed (no Agent developer access to S2 seeds/expected.json) in this single-repo context.
- **A-A6-04 [ASSUMPTION]** Planted mutations are accepted as the fault-injection method of record for MVP metrics; natural-fault generalization is delegated to the public bug-fix layer.

## UNCERTAINTIES

- **U-A6-01 [UNCERTAINTY]** Whether planted-mutation fault performance predicts natural-fault performance (distribution gap). Mitigation exists (public bug-fix commit layer, I-A6-04b) but the mineable-commit count and diff-size fit are unsurveyed.
- **U-A6-02 [UNCERTAINTY]** G13's classification carries an unreliable-first-pass caveat (F-A6-07); any Agent-level fanout claim (scenario 08 at n>100) inherits this until G13 is re-verified.
- **U-A6-03 [UNCERTAINTY]** explain_condition run-to-run nondeterminism (F-A6-07) bounds Level-1 reproducibility; the Level-2 stability budget it leaves the Agent is unquantified.
- **U-A6-04 [UNCERTAINTY]** The linker/retention truth surface was never exercised on a real project (V2-F3 NOT_RUN); G07-style retention GT beyond the synthetic linker.ld is unproven on real code.
- **U-A6-05 [UNCERTAINTY]** Whether ≥80% sufficiency is the right threshold for the OQ10 gate is a judgment call; it is pre-registered as ε/threshold precisely so it cannot be tuned post hoc.

## TOP IMPLICATIONS & QUESTIONS

1. **The one decision-relevant number for R7 is substrate-sufficiency S (I-A6-06).** It is cheap to measure (one seeded generator + one sufficiency audit over ~12 dev fixtures) and it objectively arbitrates "finish fw-context vs build the Agent" (C-04). Recommend measuring it before any substrate roadmap is accepted.
2. **MVP evaluation corpus [PROPOSAL]**: 12 planted-fault fixtures derived from existing golden bases G03/G04/G06/G07/G10/G13 (2 per FULL/PARTIAL rule type of I-A6-02) + 4 clean FP probes + sealed holdout from a second seed; metrics per I-A6-03; protocol per I-A6-04. This reuses only patterns already proven in the pack (F-A6-03) — no new oracle machinery is invented.
3. **OQ9 answer — first public end-to-end fault case with objective answer [PROPOSAL]: PFC-1 "Zephyr workq lost submission."** Base = Zephyr `tests/kernel/workq/work_queue` at the exact SHA already exercised by V2-Z3 (PASS, F-A6-07). Fault = move the first `k_work_submit_to_queue` call before `k_work_queue_start` in the fixture code (authored mutation, pinned by diff). GT = expected.json `{mechanism_class: "ordering — submit before start ⇒ work item never executes", evidence: [submit site lines, start site lines], rule_predicate: "submit precedes start in the same function with no intervening guard", forbidden_claims: ["runtime crash", "queue exhaustion", "handler bug"]}`. Scoring: localization (either site ±3 lines) + mechanism class (fixed taxonomy) + rule predicate exact + zero forbidden claims; FP probe = un-mutated base must yield no definite fault claim. Why this one: the substrate surface already PASSED (so Level-2 failures are attributable to the Agent), the rule predicate is checkable from line ordering (source-only), and both base and mutation are SHA-pinned (F-A6-10). Explicitly NOT F-V2-001/CMSIS C-form: that answer is already known wrong at the substrate layer, so it would measure Level-1, not an end-to-end Agent case.
4. **Scenario-03 needs a ruling**: either the team accepts the two-part contract (facts GT + forbidden-overclaim list) or scenario 03 is dropped from the objective MVP suite — there is no third option that keeps it objective (I-A6-05).
5. **Questions to the pack**: A1 — confirm the rule-type taxonomy of I-A6-02 as the operational definition of "rule" (OQ3) so metrics bind to it. A4 — adjudicating C-01 and C-03 gates the caveat-branch design in I-A6-04d; scoring branches cannot be finalized before that ruling. Controller — confirm fixture-authoring budget (A-A6-02) and holdout seal enforcement (A-A6-03).
6. **Reproducibility debt is load-bearing**: metrics 1–9 are only trustworthy if Level-1 nondeterminism (U-A6-03) is either fixed or explicitly excluded from scored surfaces; recommend the latter for MVP (score only deterministic surfaces) and record the exclusion.

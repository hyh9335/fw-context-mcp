## INFERENCES

- INFERENCE I1 — Bias 1 (fw-context completion bias): PRESENT. Quantified: ∞ ratio of substrate investment to goal investment (945 commits / 64.7k LOC / 107 tags / 58-case campaign / 3294 tests vs 0 lines of Agent code); the seed itself warns against exactly this (CURRENT_STATE_SEED line 9; C-04 open). The product drifted toward "standalone product" (release-tag cadence, agent-instruction templates, LLM tiers) that the contract lists as non-goals.
- INFERENCE I2 — Bias 2 (test-green bias): PRESENT. 3294 passing tests did not surface any of the 7 semantic FAIL_PRODUCT classes; those emerged only from freshly authored adversarial golden cases. FR-R1 shows the suite can encode and defend wrong semantics for release cycles. Platform-split green (WSL 0F vs Windows 10F) shows "suite green" is host-relative. Green measured unit contracts, not semantic truth.
- INFERENCE I3 — Bias 3 (static-analysis maximalism): PRESENT (moderate, not derailing). compare_variants / group_equivalent_variants / dead-code L2 exceed the goal's stated scope, and the campaign's most severe defect (F-V1-003) lives in exactly that advanced machinery — which also self-masks. No artifact ties any fw-context capability to a discovered fault mechanism or a diagnosis rule yet. Counterweight: call graph and conditional-region surfaces (PASS) do have direct fault-discovery utility.
- INFERENCE I4 — Bias 4 (LLM maximalism): NOT PRESENT in the substrate (LLM is optional enrichment; campaign ran --no-analyze; llm_analysis is documented non-evidence). But the opposite over-correction — a mostly-LLM + grep + build-tools Agent with no fw-context — also fails the contract: G04-class branch flips, G03 branch_states, and function-pointer call edges need mechanical, exhaustive, reproducible ground truth that an LLM cannot certify for goal item 5's audit requirement. Evidence-backed unique substrate value: (a) per-context ifdef views with evaluated branch states; (b) variant rows with config_hash provenance on real builds; (c) call graph incl. indirect edges; (d) a measured stdio MCP surface (warm ~15 ms, fanout 13.2 s @250 TUs). None of these is impossible via clang -E/-dM + grep + rebuilds — but they are expensive per query, uncached, and unprovenance-tracked there. CRITICAL GAP: no measured baseline exists for the LLM+grep arm (see U1) — "necessary vs optional" is currently an article of faith in BOTH directions.
- INFERENCE I5 — Bias 5 (sunk-cost bias): PRESENT, structural. See ZERO-SUNK-COST ANSWER — the from-scratch decomposition would differ materially.
- INFERENCE I6 — Bias 6 (premature MVP): NOT PRESENT in the direction feared (starting the Agent too early — Agent progress is 0%). The real observed inversion: verdicts issued prematurely on narrow scopes (READY at e7edc34 before the full-surface campaign). Starting the Agent NOW is not premature IF its first deliverable is the evidence-verification harness; the 7 FAIL_PRODUCT classes are precisely the distrust-list the Agent must operationalize.
- INFERENCE I7 — Bias 7 (single-corpus overfitting): PRESENT. Builder == fixture author == oracle author == product author (938/945 commits, one lineage); all evidence from one corporate host; 2 cases BLOCKED_ENVIRONMENT on the toolchain-less hosts typical of the target audience; "public real" = 5 embedded-RTOS repos only, while the goal says "firmware/software" — no non-embedded corpus ever touched.

## TOP IMPLICATIONS & QUESTIONS

- PROPOSAL P1: Invert the roadmap immediately: Agent first, verification-harness-first. Its v0 consumes fw-context as an UNTRUSTED evidence source with explicit distrust rules: empty ⇒ unknown (not absent); every load-bearing positive re-anchored to source; negatives re-verified externally. The 7 FAIL_PRODUCT classes become the harness's first guard tests.
- PROPOSAL P2: Kill criteria (role mandate): KC-1 — if per-context macro values are not exposed (or raw-export bypass provided) within the first Agent sprint, switch the config-conditions channel to direct `clang -dM -E` + build queries and demote the substrate there. KC-2 — run the held-out experiment: ≥30 real bugs from the 5 RTOS repos' fix histories; substrate-arm vs grep+build+LLM-arm, pre-registered precision/recall margin on fault mechanisms; if the substrate-arm does not win, demote fw-context to optional cache. KC-3 — if >10% of sampled substrate negatives prove false during Agent operation (current false-negative baseline: F-V2-001, F-V1-005), zero trust budget for negatives and re-cost the substrate against the verification overhead it forces. KC-4 — if C-01 is unadjudicated at R7, treat both verdicts as unusable and demand external replication of the 58-case campaign before "certified" language is used in any Agent decision.
- QUESTION Q1: What is the measured KC-2 baseline? Without it, the GOAL_CONTRACT requirement "which fw-context capabilities are necessary vs optional" is unanswerable — and so is this review's central tradeoff.
- QUESTION Q2: For F-V1-003, is per-variant compile_commands isolation a substrate fix, or should the Agent mandate one-build-context-per-index as an operational rule? The rule is cheaper and eliminates the defect class without substrate surgery.
- QUESTION Q3: Should the substrate ship a raw-evidence export (macros, single-line bodies, per-context rows) so the Agent bypasses query-layer interpretation? Evidence says the data already exists (F-V1-001, G10 refs) — highest leverage per line of code in the whole roadmap.
- IMPLICATION: Any R7 roadmap line that fixes fw-context without naming the fault/rule-discovery impact violates the A0 rule (C-04) and should be struck.

## ZERO-SUNK-COST ANSWER (mandatory, explicit)

> If this project started today with zero sunk cost, would we choose the same decomposition and the same role for fw-context-mcp? If not, what changes?

**NO — the concept survives, the current role and scope do not.**

1. KEEP (zero-sunk-cost defensible): a libclang-over-compile_commands index with per-context storage, because the campaign certifies exactly the surfaces a source-grounded fault agent cannot get elsewhere cheaply: per-context ifdef views with evaluated branch states (G03 branch_states verified), call graph incl. function-pointer edges (V2-F1/F2 PASS), variant provenance on real builds (Z2/N2 PASS), fast stable stdio (warm ~15 ms). A pure-LLM agent cannot certify these mechanically; pure grep/rebuild cannot cache or provenance-track them.
2. CHANGE — decomposition inverted: the Agent is the product and is built first, with its evidence protocol (mechanism → conditions → config → source anchor → falsification test) specified before any further substrate work. fw-context is commissioned as a focused evidence provider for that protocol, roughly one-third its current surface: index + per-context views + call graph + provenance + a raw-evidence export.
3. CHANGE — cut from the from-scratch scope (all present today, all orthogonal to the goal): LLM enrichment tiers and embeddings, agent-instruction templates/OpenCode scaffolding, 107-release product engineering, cross-platform closeout ceremony depth, variant-equivalence diagnostics beyond what fault discovery consumes. GOAL_CONTRACT already lists "best-in-class standalone product" as a non-goal; the git record shows the build drifted into it.
4. CHANGE — mandate substrate skepticism as architecture, not etiquette: an independent verification channel (per-variant rebuild, clang -E/-dM, grep) exists from day one, justified by facts, not prudence — F-V1-003 self-masking and C-03 absence-ambiguity mean a single-source-of-truth substrate will always be structurally unable to certify its own negatives.
5. CHANGE — consumer-first contracting: every surface the Agent consumes gets a machine-checkable contract (empty ⇒ unknown vs absent; explicit caps — F-V1-008; fallback markers — F-V2-002). The campaign found these violations because no real consumer existed; building the consumer early is the cheapest honesty mechanism available.
6. EVIDENCE THAT WOULD CHANGE MY MIND (kills the red-team position): (a) a KC-2 run where the grep+build+LLM arm matches or beats the substrate-arm on the held-out bug set → then demote fw-context to cache and say so; (b) external replication of the campaign's FAIL_PRODUCT set finding them substantially oracle-defects → then the substrate is closer to ready than this report claims; (c) evidence that per-context macro/branch-state facts were obtainable by plain LLM+grep at comparable cost and reliability in the measured environment (proxy-restricted, toolchain-less Windows host) → then the substrate's unique-value column collapses to latency only.

Bottom line for the panel: the project has spent ~4.2 months and 945 commits reaching a certified-NOT_READY substrate and a 0%-complete goal; the single highest-value next commit is the first line of Agent code — a skeptic harness — not substrate wave number N+1.

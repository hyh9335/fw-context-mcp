# R1 — A3 Evidence Rule Specialist

Scope: what a detection/diagnosis "rule" IS (OPEN_QUESTIONS 3), which rule types are validatable with source-only ground truth (OQ 4), what evidence blocks hallucinated causal chains (OQ 5), which semantic relations are MVP-critical (OQ 6). Labels per workflow/EVIDENCE_RULES.md.

## FACTS

- F1. [FACT] Substrate evidence-quality surfaces are explicit and queryable: call sites carry a 3-level `certainty` (`exact` | `possible` | `unresolved`), `resolution_kind` (`ast_direct` | `name_fallback` | `unresolved`), and `candidate_usrs` listing every alternative for possible resolutions (src/fw_context_mcp/indexer/models.py:61-92).
- F2. [FACT] The `refs` table is kept AST-proven by design (ADR-004 layer 1); every fallback resolution lives in `call_sites`, never as a refs edge (models.py:65-66; indexer/ops.py:2022-2028). The cross-TU backfill writes discoveries as certainty='possible'/origin='cross_tu_backfill' and explicitly never as refs 'call' edges that would re-enter graph tools labelled exact (ops.py:2114-2119).
- F3. [FACT] File content is a per-context fact (ADR-002): files rows are UNIQUE(config_hash, path, context_id) in rows/3; the same TU under two -D sets is two rows; conditional-region rows record which branch the preprocessor took per context (src/fw_context_mcp/indexer/db/_schema.py:590-592, 501-522, 444-451).
- F4. [FACT] lookup_symbol exact=True silently returns did-you-mean suggestions when the name is absent, marked only `_fallback: True` (mcp/handlers/_lookup.py:180-199); additionally a macro fallback returns macro rows for any unmatched symbol name (_lookup.py:161-178). This is the code mechanism behind F-V2-002 (automated existence checks get false positives; FACT_LEDGER F-R0-09).
- F5. [FACT] Single-line definitions store symbols.source='' and are invisible to search_bodies; get_source masks this via disk fallback with source_origin='disk' (F-V1-007 / F-R0-17). Per-context macro values ARE stored in the macros table but no consumer surface exposes them, and macros.expanded_value is self-inconsistent for one context ('1' vs '2') (F-V1-001 / F-R0-16).
- F6. [FACT] Known substrate failure modes bound what a rule pipeline can trust (F-R0-05..09): F-V1-003 — bare-generator writes one shared compile_commands.json so last variant's defines win, and compare_variants/group_equivalent_variants validate the collapsed data (defect invisible to the product's own consistency checks); get_source(variant='B') served the INACTIVE branch from disk with no stale warning (F-R0-06). F-V1-004 — transitive callback registration (may-target via register_cb(call-argument)) unresolved, so the reachable callback set is silently under-reported (F-R0-08). F-V1-005 — on compile_commands-only projects the plainly live chain main→live_root→live_leaf is misreported graph_unreachable because the root set requires a build-attested linker script; manual backend never links and no key declares one (F-R0-07). F-V2-002 — exact=True false positives (F4).
- F7. [FACT] An empty get_vector_table result has two distinct readings: contracted-honest (unsupported arch / fixture skip, FR-NEW-4) vs false absence (standard CMSIS6 C-template form, F-V2-001) — registered as contradiction C-03 (CONTRADICTIONS.json).
- F8. [FACT] Dispatch-synthesized edges (event loops, thread starts) are traversed only through a built-in bridge map (mbed-os/Zephyr/FreeRTOS) plus config-declared bridges, each pinned to exact C signatures; a bridge whose entry symbol is not indexed is skipped silently (find_call_path contract; indexer/_dispatch_bridges.py:99-161). trace_data_flow explicitly excludes queue semantics (EVENT_SEND/RECEIVE ordering) from the call-graph model.
- F9. [FACT] The review's own discipline already encodes two rules the Agent must inherit: never treat green tests as semantic truth without an independent oracle; never make a fw-context bug roadmap-critical unless its impact on fault/rule discovery is explained (workflow/EVIDENCE_RULES.md).
- F10. [FACT] No fault-discovery/rule-generation code exists in the repo (F-R0-18): the rule layer is greenfield; only substrate evidence surfaces and the review discipline exist.

## INFERENCES

### Rule taxonomy (PROPOSAL — core deliverable; answers OQ 3)

Per type: (a) source-only-GT validity, (b) required substrate evidence, (c) FP control, (d) hallucination risk. "Source-only GT" = re-derivable from source + build inputs alone, no runtime artifacts.

**R1 — Syntactic code-pattern rule.** "Pattern P holds at location class L in compiled context C."
- (a) VALID per-context. GT is the *compiled view* (ifdef-filtered), never the raw file — a raw-file match may be a dead branch.
- (b) files.content per context (rows/3), match_lines, symbols.source, source_origin, row_format.
- (c) Artifact gate: refuse body-derived claims when row_format < fw-context-rows/3 (rows/1 kept inactive branches; _schema.py:84-86, maintenance.py:389), when source_origin='disk'/stale (F-V1-007 masking path), or when stored source='' for a plausible one-line definition (F-V1-007). Corroborate on ≥2 surfaces before asserting.
- (d) LOW — failure mode is artifact-confusion, not invented causality. **MVP-viable.**

**R2 — Symbol-graph structural rule.** Registration, edge existence, may-target enumeration, dead-code claims.
- (a) SPLIT: positive edge claims = source-only valid iff certainty='exact'. May-target enumeration = LOWER BOUND only (F-V1-004 proves the set is under-reported). Reachability/negation = NOT source-only-GT-validatable today on compile_commands-only projects (F-V1-005/G07); sound only where a build-attested linker script exists (F-R0-07 notes KEEP-protection works with a linker oracle).
- (b) refs (call/indirect/implicit_construct), call_sites.certainty+candidate_usrs, vector-table rows incl. coverage + unhandled complements, find_indirect_targets assignments.
- (c) Polarity discipline: positives require exact; absence claims require include_possible traversal + unresolved_count + vector coverage rows; reachable-set claims always stated as lower bounds.
- (d) MEDIUM — F-V1-004 and F-V1-005 are precisely the FP/FN cases for this type. **MVP-viable only as lower-bound form; dead-code rules blocked on G07.**

**R3 — Build/config-conditional rule.** "In variant/image B, branch X compiles; feature F active iff -DF."
- (a) VALID IN PRINCIPLE (defines+directives fully determine branches), INVALID AS DELIVERED on bare-generator projects: F-V1-003 collapse, self-masked by the product's own consistency tools.
- (b) config_hash on every row, conditional_regions branch states (1/0/-1), explain_condition chain + macro_inputs, build_contexts, per-row (variant, image, config_hash) tuple.
- (c) Hard provenance discipline: never join rows across config_hash; require branch-state text to match directive text; distrust any body whose context_id contradicts the claimed variant. No in-band self-check is trustworthy here (F-V1-003) → needs out-of-band re-derivation (see T4).
- (d) HIGH today — the substrate emits no signal when variants collapse. **MVP-viable ONLY on projects with per-variant compile_commands (the collapse is bare-generator-specific per F-R0-05) and only with tuple discipline.**

**R4 — Macro/definition existence rule.** "Macro M defined with value V in context C"; "symbol S exists."
- (a) VALID — macros fully determined by command line + file text.
- (b) macros table (values stored, def_source), `_fallback`/`_did_you_mean` markers, expanded_value.
- (c) Existence = result WITHOUT `_fallback` marker and kind-consistent (the macro fallback must never answer a symbol question — _lookup.py:161-178). Absence = re-ask via independent phrasing (prefix query / second tool) before asserting. Distrust expanded_value for multi-context macros (F5).
- (d) MEDIUM — silent fallbacks convert "absent" into "exists (wrong symbol)" inside one call. **MVP-viable with marker discipline.**

**R5 — Runtime-observable rule.** "When E happens at runtime, symptom S appears" (assert fires, log line, watchpoint).
- (a) NOT source-only. Only the emission site is source-verifiable ("branch X can emit E"). The E→S binding requires a runtime artifact.
- (b) Ifdef-filtered body + line anchor of the emission site; mandatory `validation_status: source_derived | trace_confirmed` field (PROPOSAL).
- (c) source_derived rules may only claim "the code CAN emit E here", never "E causes S"; trace confirmation is out-of-band GT.
- (d) HIGH — the archetypal hallucinated causal chain. **NOT MVP-viable as diagnosis rules; viable only as emission-site facts.**

**R6 — Causal diagnosis rule.** "Preconditions P1..Pn (code+config) → fault F via mechanism M."
- (a) SPLIT BY DECOMPOSITION: the precondition conjunction IS source-only-validatable (each Pi is an R1/R2/R3/R4 fact); the implication P→F is NOT. Source-only GT proves "all preconditions hold in context C", never "therefore F".
- (b) Union of the above, each with per-claim certainty + provenance.
- (c) Rule confidence = min over precondition certainties; any precondition resting on a 'possible' edge caps the whole rule at "hypothesis"; every implication carries `mechanism_status: unverified` until a runtime artifact or human adjudication.
- (d) HIGHEST — invented causal chains live exactly here. **MVP form: decomposed "condition-conjunction + flagged implication", not one-shot causal assertion.**

**R7 — Invariant rule.** "Property I holds over scope S" (lock released on every return path).
- (a) ASYMMETRIC: falsifiable by one counterexample; never provable source-only in general (needs exhaustive path/variant enumeration).
- (b) All-context conditional-region coverage + all-path graph closure — beyond current substrate guarantees.
- (c) Must state explicit scope ("in every indexed context of config_hash X") + a counterexample protocol.
- (d) HIGH if universal, LOW if scoped. **MVP: scoped-falsifiable form only.**

**R8 — Event-sequence rule.** "A then B without C" (init/use order, IRQ mask/unmask pairing).
- (a) SPLIT: steps joined by exact call edges on synchronous paths = source-only valid; any step through a dispatch bridge, queue, ISR ordering, or callback interleaving is NOT (F8: queue semantics excluded, bridges pinned-signature only, silent skip).
- (b) find_call_path exact edges, find_indirect_call_sites/targets, dispatch-bridge declarations.
- (c) One non-exact step downgrades the entire rule to "possible ordering"; async steps need runtime confirmation.
- (d) LOW (synchronous) / HIGH (async). **MVP: synchronous-only.**

### MVP viability verdict (INFERENCE; answers OQ 4/6)
MVP rule set given F1-F10: R1 + R4 + R2-as-lower-bound + R3-with-provenance-discipline (per-variant projects) + R6-decomposed + R7-scoped + R8-synchronous. Deferred: R5 as diagnosis rule, R2 reachability negatives (dead-code), universal invariants, async sequences. MVP-critical semantic relations, in order: per-context/variant identity (F3), exact-vs-possible call edges (F1/F2), indirect/callback targets as lower bounds (F6), compile conditions (F3), vector-table registrations (F7). Reachability, async ordering, and runtime bindings are NOT MVP-critical because they are not source-only-verifiable and their current surfaces carry the worst failure modes.

### Cross-cutting evidence principles (INFERENCE)
- I1. **Polarity asymmetry is the central FP-control device.** The substrate's known failures are polarity failures: F-V1-005 (false absence of reachability), C-03/F-V2-001 (empty vector table = honest-empty or false-absent), F-V2-002 (false existence). Therefore: exact evidence licenses positive claims; absence claims need multi-surface + possible-edge + coverage corroboration; sets are stated as bounds, never closures.
- I2. **Per-context provenance is non-negotiable.** Every evidence row is (config_hash, context_id)-scoped by schema (F3); every rule conclusion must inherit the same tuple. Context-collapsing is exactly how F-V1-003 became invisible.
- I3. **The producer must not be the validator.** F-V1-003 is self-masking because compare_variants/group_equivalent_variants validated data produced by the same pipeline. A rule framework whose audit step reuses the substrate's own consistency tools inherits those blind spots — this is a direct answer to OQ 10 (local-optimum evidence: tools that validate what they produce).
- I4. **Certainty is typed, not scalar.** certainty × resolution_kind × origin × source_origin × context tuple must ride on every rule fact. A single confidence number destroys the exact/name_fallback distinction that F2 keeps alive at the schema level.

## ASSUMPTIONS
- A1. [ASSUMPTION] The rule layer can consume raw substrate rows (certainty, context_id, candidate_usrs, origin) — i.e., it talks to the substrate at row/export level, not only through prose tool answers. Unverified: no Agent code exists (F10).
- A2. [ASSUMPTION] The first public fault case (OQ 9) will be chosen so its preconditions are expressible as R1-R4/R8-sync facts; if it requires an async or runtime-bound mechanism, MVP scope changes.
- A3. [ASSUMPTION] Bare-generator variant collapse (F-V1-003) does not affect projects whose build emits per-variant compile_commands.json; the finding attributes the defect to the shared-file generator path.

## UNCERTAINTIES
- U1. [UNCERTAINTY] Whether `possible` rows' candidate_usrs lists are complete. F-V1-004 shows the may-target set is under-reported at the registration-flow level; whether candidate lists themselves can silently drop entries is untested.
- U2. [UNCERTAINTY] explain_condition context resolution is nondeterministic across runs (F-R0-15, G03: context A vs B in different runs). Whether this can flip R3 rule preconditions between runs is material and unresolved.
- U3. [UNCERTAINTY] The R3 boundary case where the build system itself lies (stale compile_commands): no source-only validation exists there. Accepted as a hard limit, not solved.
- U4. [UNCERTAINTY] Whether vector-table 'build'-source rows (generator-resolved addresses) can ever support absence claims — they name in-use slots but leave coverage holes; untested here.

## TOP IMPLICATIONS & QUESTIONS
- T1. - T2. [PROPOSAL] MVP gate applied to every candidate rule: (1) all evidence rows are rows/3-format; (2) per-context tuple present on every fact; (3) no `_fallback` markers on existence facts; (4) polarity matched to evidence certainty per I1; (5) llm_analysis never cited (EVIDENCE_RULES). These five checks would have caught F-V1-007, F-V2-002, and most of F-V1-003's blast radius at rule level.
